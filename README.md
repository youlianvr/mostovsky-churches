# Дорогами духовности — маршрут по храмам Мостовского района

Школьный проект по истории: сайт-маршрут по трём действующим православным церквям
Мостовского района (Гродненская область, Беларусь) — **Гудевичи → Лунно → Дубно**.
Это Блок 1 «Дорогами духовности» конкурса «Гродненщина православная»
(туристско-краеведческий), поэтому сайт состоит ровно из шести его обязательных
элементов: нитка маршрута, карта-схема, описание, логистика, справочная информация,
фотоотчёт.

## Стек
Чистые HTML/CSS/JS, без сборщиков и внешних CDN. Данные — в `js/data.js`.
Роутинг — `#/slug`. Размещение — GitHub Pages.

## Структура
```
├── index.html          ← приложение: пять отделов + страницы храмов
├── about.html          ← «О проекте», задание и источники
├── css/style.css       ← дизайн-токены и стили (единый источник)
├── js/data.js          ← ВСЕ данные, тексты и правила целостности
├── js/router.js        ← разбор адреса, порядок маршрута, поиск по slug
├── js/map-geometry.js  ← модель схемы: реальная геометрия OSM (граница района,
│                         Нёман, дороги) и проекция координат
├── js/church-icon.js   ← единый условный знак: иконка церкви (SVG)
├── js/dom.js           ← строители разметки; единственный писатель #app
├── js/map.js           ← SVG схемы: иконки, нитка, легенда, клавиатура
├── js/sections.js      ← пять отделов-страниц Блока 1 и их список
├── js/church.js        ← страница храма, локатор района, фотоотчёт храма, 404
├── js/app.js           ← диспетчер: адрес → отдел или страница храма
├── img/photos/         ← фото храмов (атрибуция в data.js → photoCredit)
│   └── visit/          ← сюда лягут личные фотоотчётные снимки
├── tests/              ← контракты без фреймворка (см. tests/README.md)
└── MASTER-PLAN.md      ← план, решения (DG) и что автор закрывает сам
```

`index.html` грузит модули в порядке зависимости — ровно этот список сверху вниз,
и он же записан тегом `<script>` в самой странице. `about.html` статичен и не грузит
ни одного скрипта. Ни HTML, ни CSS не знают о данных: всё, что читает код,
описано в `js/data.js`, где при загрузке проверяется целостность (пустые поля,
неизвестная конфессия, неполная логистика, расхождение `routeStep` с порядком `ROUTE`,
остановка без рейсов, пункт питания без пометки проверки).

Что живёт в `js/data.js` отдельными блоками, кроме самих объектов:

| Блок | Что описывает |
|------|----------------|
| `CHURCHES` | тексты, контакты, история, километраж, короткая строка про автобусы |
| `ROUTE`, `ROUTE_LEGS`, `ROUTE_APPEAL` | порядок остановок, перегоны, обоснование привлекательности |
| `BUS` | транспортные узлы: автовокзал Гродно и автостанция «Мосты» — адрес, телефон, часы |
| `BUS_STOPS` | расписание у каждой остановки: направление, маршруты, время и дни, путь до храма |
| `FOOD` | пункты питания в Мостах; у каждого — часы и пометка «проверено» |
| `SOURCES`, `PHOTO_REPORT` | чек-лист источников и слоты фотоотчёта (рендерятся на странице каждого храма) |

## Проверка


## Как править контент после сдачи
1. Открыть нужный файл в веб-интерфейсе GitHub (иконка карандаша).
2. Текст, координаты, контакты — в `js/data.js`; стили — в `css/style.css`.
3. Если правился `css/style.css` или файл из `js/`, поднять номер версии у этого
   файла в `index.html` (`style.css?v=25` → `?v=26`); `style.css` — ещё и в
   `about.html`: иначе браузер посетителя отдаст старую копию из кэша.
4. Commit changes → сайт обновится через 1–2 минуты. Инструменты не нужны.
