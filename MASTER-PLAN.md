# Мастер-план: «Храмы Мостовского района»

Ревизия спецификации от 2026-09-01. Статус: план утверждён по Decision Gates,
готов к исполнению. Роль агента: full-stack исполнитель школьного веб-проекта
(research + frontend, без Node.js/сборщиков).

## Уровень A — Подтверждённые факты (не пересматривать без новых доказательств)

- Район: Мостовский район Гродненской области, Беларусь (не Краснодарский край).
- Маршрут: **17 объектов** — 12 православных + 5 католических. Доп.кандидаты
  (Малые Степанишки, Понижаны) **в маршрут не входят** — решено владельцем.
- Маршрут кольцевой, старт/финиш — г. Мосты, спроектирован владельцем.
- Карта: гибрид — схематичная SVG-карта района + кнопка «Открыть на карте»
  (Яндекс.Карты основная, OSM запасная) у каждого объекта.
- Хостинг: **GitHub Pages, репозиторий публичный** — решено владельцем.
- Архитектура: одностраничник + `data.js` (единый источник данных),
  роутинг через `#/slug`, без сборщиков, без внешних CDN.
- Контент: полная история (2–4 абзаца) + факты на странице каждого объекта.
- Фото: только с атрибуцией (автор, лицензия, ссылка); без атрибуции — не использовать.
  Приоритет источника — Wikimedia Commons.
- Язык: русский; беларусские названия — опционально в скобках.
- Файловая структура, схема данных объекта — спецификация §3.2–3.3, без изменений.
- planetabelarus.by подтверждён владельцем как источник точных координат —
  проверить по всем 17 объектам, в дополнение к OSM Nominatim, orthos.org,
  sobory.ru, Википедии.
- Сбор контента — лёгкий этап; недооценённый риск — бесконечные правки UI/UX.
  Вёрстка и полировка — итеративный блок с watchdog-контролем.

## Уровень B — Гипотезы (подтвердить исследованием на этапе 1)

- Часть объектов (Мосты — Ильинский, Софии Слуцкой; Пески правосл.; Плодовая)
  не имеют точки в OSM — гипотеза: planetabelarus.by закроет большинство.
  Софии Слуцкой (строится с 2011) может не иметь устоявшейся точки в принципе.
- Не все 17 объектов есть на Wikimedia Commons.
- Краеведческие источники местами противоречат друг другу по датам постройки.

## Уровень C — Decision Gates

| DG | Вопрос | Статус | Решение |
|----|--------|--------|---------|
| DG1 | Приватность репозитория | **Решено** | Публичный, бесплатный GitHub Pages |
| DG2 | TBD-координаты и доп.кандидаты | **Решено** | 17 объектов; TBD через planetabelarus.by |
| DG3 | Запасной план по срокам | **Решено** | Контент не урезать; резерв — в UI/UX-этап |

## Этапы (топологический порядок)

### Этап 0 — Baseline & guardrails ✅ (выполняется)
- Публичный репозиторий mostovsky-churches на GitHub.
- git init, файловая структура-скелет (§3.2).
- Research ledger (RESEARCH.md) со статусами по 17 объектам.
- Точка отката: первый коммит = скелет без контента.

### Этап 1 — Research: координаты и контент (блокирует этапы 6, 9)
- По каждому из 17: planetabelarus.by (приоритет), orthos.org, Wikipedia ru/be,
  sobory.ru, poshyk.info/ldd.by.
- В ledger: точные координаты (или fallback DG5), 2–4 абзаца истории с
  источником, 3+ факта. При расхождении дат — «по разным данным: 1915/1918».
- Результат: data.js полностью заполнен текстом и координатами (фото — заглушки).

### Этап 2 — Фото (параллельно с этапом 3)
- Wikimedia Commons, лицензии CC BY / CC BY-SA / CC0. Атрибуция в photoCredit.
- Нет фото → placeholder + «фото уточняется», gap в ledger, не блокирует.

### Этап 3 — Фундамент: data.js + дизайн-токены
- Структура объекта (§3.3), tokens в style.css (#f5efdf, #2f4a32, #b58a4a,
  серифные заголовки, крупный кегль). Никаких инлайн-стилей.

### Этап 4 — Каркас сайта
- index.html, about.html, app.js (роутинг #/slug, рендер из data.js), навбар.
- Placeholder-контент; цель — рабочая навигация.

### Этап 5 — SVG-схема и маршрут
- map.js: контур, Неман, дороги, НП; 17 меток с номерами; пунктир маршрута.
- DG4 дефолтом + визуальное ревью с владельцем (не финал до подтверждения).
- Легенда: круг/квадрат.

### Этап 6 — Наполнение контентом (зависит от 1, 2, 4, 5)
- Полный текст, фото, координаты из data.js во все 17 страниц через роутинг.
- Проверка: заголовок, крошки, фото+подпись, панель фактов, история, факты,
  «Открыть на карте», пред/след.

### Этап 7 — UI/UX-полировка (итеративный цикл, приоритет владельца)
- Адаптивность (мобильный/планшет/проектор, тест 1280×800 и mobile),
  доступность (контраст, alt, клавиатура), визуальная согласованность,
  edge cases (слитые метки, отсутствующее фото, длинные названия).
- Каждый цикл — реальный визуальный проход (скриншоты разных ширин).

### Этап 8 — QA / регрессия
- 34+ ссылок «Открыть на карте», роутинг (17 slug + #/about + неизвестный slug),
  атрибуции фото, офлайн-открытие двойным кликом.

### Этап 9 — Деплой
- GitHub Pages (source = ветка/корень), проверка публичной ссылки с реального
  устройства, README: как править data.js через веб-интерфейс GitHub.
